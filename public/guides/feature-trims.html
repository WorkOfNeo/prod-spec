The trims list

Every order carries a Trims list on Monday — the buyer’s own words for what the order needs. This screen is where those words are given a meaning, so the cover page can print the list and say which lines we produce.

Settings ▸ Trims. Nothing here renders a PDF, sends anything, or arms a queue — it only decides what words mean.

1 Why words need a meaning at all

The cover page prints the buyer’s trims list in Monday’s own words, so the supplier can tick it off, and marks each line as something we produce, something supplied separately, or a packing instruction with no artwork. To do that it has to recognise what each line is.

A trim is never matched to one layout. “Care label” exists once per client, so that mapping would never be finished — it would have to be redone for every new customer. Both sides are matched onto a shared packaging row instead — one of the lines a cover page can print, written once for everybody on Settings ▸ Cover page ▸ Packaging rows (guide 3):

Monday saysWash Care Label with Oeko-tex Logo
A layout is calledAcme Apparel - Kids - Care Label
→
the packaging row Care label
A style satisfies a trim when any document it already declares lands on the same row. So “Hangtag” is produced by us for a client who has a hangtag layout, and supplied separately for one who doesn’t — with no per-client setup.
Some rows have no artwork — on purpose

A large share of live trims are physical packing instructions with nothing to print: master polybags, hangers, cartons, hooks. Those are listed on the cover so it matches the buyer’s list one for one, but as a note — never as a document with a delivery status, which would otherwise sit at “waiting” forever and bury the lines genuinely waiting. Whether a row is a document or a packing instruction is set on the row itself, on the Packaging rows tab.

One mapping, two screens to edit it from

This screen works value first: here is a Monday word, which rows does it mean? Settings ▸ Cover page ▸ Packaging rows works row first: here is a line the cover prints, which Monday words land on it? They are the same mapping seen from opposite ends — a change made on one shows up on the other, so neither can go stale.

Use this screen to work through the queue of words that have no row yet. Use the other when the question is “what actually ends up on the hangtag line?”

  2. 2Rules — the ordered keyword rules that classify both sides. Order is meaning here: the first rule that matches wins, so sorting the list alphabetically would silently re-label thousands of styles. The screen says so in an amber banner, and the arrows move a rule up or down.

  4. 4Only show what needs a decision is on by default, on both the Trim values and Layouts tabs. It hides everything already resolving cleanly. Untick it to see the whole vocabulary.
  5. 5Everything saves in one press. Edits are collected locally and sent together, because a half-applied rule set classifies like neither the old one nor the new one. The page reloads afterwards so every count on screen is recomputed rather than half-patched.

3 Only the words that still matter

The list used to cover every style ever scraped, which meant vocabulary from long-dead orders sat in the queue and shaped the rules for orders nobody will ever print. It is now scoped to the generation PO cutoff — only orders that will actually be printed.

164 distinct values across the whole book → 88 once scoped to the generation cutoff (PO 100000 and above). 76 values live only on orders we will never print, and are no longer asked about.
812 styles in scope · 4,930 parked below the cutoff · 260 with no PO number at all. 3 carry a PO number that doesn’t parse onto the timeline — those are kept, because generation keeps them too.
  • 1Below the cutoff — the order predates what we print. Its words are parked, not deleted.
  • 2No PO number at all — a placeholder that will never be delivered. Its words are not put in front of anyone.
  • 3A PO number that doesn’t parse — kept, because generation keeps those styles too. The numbers are shown separately so the split is visible rather than assumed.

This is the generation cutoff specifically — not the scrape cutoff (how far back we re-pull data) and not the supplier-send cutoff (what leaves the building).

4 A suggestion versus a decision

Most values need nothing from you. The keyword rules already resolve them, and while nobody has said otherwise the value simply follows the suggestion — so if a rule is later improved, the value improves with it. Picking rows yourself is a different thing: it becomes a stored decision that no later rule change can move.

A value can name more than one row, which is why the Decision column is a set of chips rather than a dropdown. A compound Monday entry like “Polybag + Inlaycard + Hangtag” is one line naming three things, and a single-choice control would quietly drop two of them.

  1. 1“suggested” — a keyword rule matched and this value is following it. Nothing needs doing; it keeps following the rules as they improve.
  2. 2“check” — several rules matched and the first one won. It is probably right, but a person should confirm it. These count toward the tab’s “to check” number.
  3. 3“no row yet” — genuinely new vocabulary. Nothing recognises it, so the cover prints the line as supplied separately until somebody maps it. That is the safe direction: a supplier never loses a line while it waits.
  4. 4“decided” — a person picked these rows. The rules can no longer move it. Several chips means the one Monday entry prints on several cover lines, which is exactly right for a compound entry.
  5. 5Accept suggestion turns the rule’s proposal into your decision, unchanged. It only appears while the value is still following the rules.
  6. 6Undecide hands the value back to the rules — the opposite of Accept. It only appears on a value somebody has decided.
  7. 7Not packaging keeps a value off the cover entirely, and it is a stored decision like any other. Use it for one-offs typed into the column that aren’t trims — a PO number, a note to the buyer. Removing the last chip from a value does the same thing.
Accept all — the shortcut for the common vocabulary

When values are still following the keyword suggestion, a panel above the table says so and offers Accept all. It turns every one of those suggestions into a decision of your own in a single click.

Two things it deliberately does not do. It does not touch values that no rule matched — those still need a person, and mapping them to nothing would call the job done while the queue was still full. And it changes nothing about what covers print today: those values already print exactly this way. What accepting buys you is that a later rule edit can no longer move them.

Choosing a row

The Add a row… picker lists the whole shared list: care label, carton marking, colour sticker, hangtag, banderole, neck print, main label, size label, price sticker, barcode sticker, polybag sticker, info area / insert card, top card, pictogram, heat transfer, RFID — and the ones marked (no artwork): polybag, hanger, carton/box/display, hook, packing instruction. Picking a “no artwork” row means the line prints as a note, with no delivery status.

Nothing in the list fits? Rows are added on Settings ▸ Cover page ▸ Packaging rows (guide 3). The screen links straight there; add the row, come back, and pick it. Rows somebody has removed are not offered, but a value already pointing at one keeps working.

Start the vocabulary over — admins only

Decisions made before the list was scoped may have settled words no live order uses any more. Review stored decisions… shows exactly what is stored, how many in-scope styles still use each, and how many are parked — then lets you drop the lot. That re-opens every value for mapping; the keyword rules and the layout pins are left alone. It cannot be undone from here: each decision has to be made again.

In practice: open the Trim values tab, leave the filter on, and work down the short list. Confirm the “check” rows, give a row to the “no row yet” ones, mark anything that isn’t a trim at all as Not packaging — then Save. If most of the list is still on a suggestion and you are happy with it, Accept all clears it in one go. If the same word keeps reappearing in slightly different spellings, the better fix is a keyword on the Rules tab, not a decision per spelling.
