General information, and re-issuing one order

The requirements pages that print inside every bundle, written per client and business area — and the two ways to push a change out to bundles that already exist.

Settings ▸ Cover page ▸ General information — the middle of three tabs, beside Cover page (all clients) and Packaging rows (guide 3). Reviewers own this prose, so this is the one Settings screen in a reviewer’s sidebar.

1 Where this text ends up

A bundle opens with the cover page block, which is the same for every client. General information comes straight after it, inside the same cover PDF — and unlike the cover block, there is one set per client and business area. Quality standards, AQL tables, packing requirements: whatever this client needs to say on every order.

2 Saving affects bundles generated from now on

Existing bundles keep the text they were built with

A cover PDF is rendered when a bundle is generated and then frozen. Editing this text does not reach back into bundles that already exist — including any already delivered to a supplier. They keep their old wording until something rebuilds them.

That is usually what you want. When it isn’t, there are two tools directly below the editor, and the difference between them is scope.

Regenerate a style

  • One style number, across every order carrying it.
  • For “this order went out with the wrong text”.
  • Section 3.

Apply to existing bundles

  • Every style under the client and business area you have open.
  • For a wording change everybody should see.
  • Section 4.

3 Regenerate a style

Type a style number, see exactly which orders carry it, then rebuild those covers and push them straight back into the suppliers’ folders — replacing the copy each supplier holds now.

A style number is not one order

The same number normally appears several times — once per purchase order, and once per colourway. Correcting “that style” means all of them, so the search names every match and the run works through the whole list. “Found 4, fixed 1” would leave three suppliers on the old PDF while the app read as done.

The search covers every client — and that is safe

The number you type is the number you want fixed, whichever client’s tab you happen to have open. A match belonging to a different client is allowed and is labelled as such, because its cover prints that client’s General information — each style is always rebuilt against its own client’s text, never against the one on screen.

Each style is rebuilt and pushed in turn, so it takes a moment per style, and the result reports every one of them separately. “Rebuilt” and “delivered” are separate facts and either can fail on its own, so a run where one of four failed never renders as a single green tick.

4 Apply to existing bundles

The broad instrument: rebuild the cover PDF of every style under the client and business area you have open that was generated before your edit. Right after a wording change everyone should see; much too broad when one order needs correcting.

It counts the styles first, then asks you to confirm with three choices:

  1. 1Skip styles where every output is approved — on by default. Their cover shows no status column at all, so rebuilding changes nothing a supplier can see, while still overwriting the file for an order that is already finished. Untick it only if you changed something that shows on every cover.
  2. 2Push updated covers to the suppliers’ folders — on by default, overwriting the copy they hold. Untick to refresh the covers in-app only.
  3. 3Skip covers that already say the right thing — on by default. Each rebuild records what it printed, so a second run costs nothing and a stopped run resumes where it left off.
No supplier is emailed, and there is no option to

Unlike Regenerate a style, this tool has no email checkbox at all. The updated file simply becomes the current one in the folder. That is deliberate: a bulk refresh across old orders means the wording changed, not that anybody’s order did — and a few hundred emails saying so would be noise.

If a particular supplier genuinely must read the change, use Regenerate a style on their order and tick Also email the suppliers there.

Either way, outputs and approvals are untouched

Both tools rebuild the cover PDF only. No layout is re-rendered, no approval is reset, and nothing is sent back for review.

Which one? If a supplier is holding a PDF with the wrong text for one order, use Regenerate a style — type the number, check the list, run it. If you have just rewritten the requirements everybody works to, use Apply to existing bundles and leave the defaults alone.
