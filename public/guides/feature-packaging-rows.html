Writing what the cover page says

Every packaging line a cover page can print is written once, here — its name, the standing note under it, the two wordings its status column uses, and which of the buyer’s own trim words land on it.

Settings ▸ Cover page ▸ Packaging rows, the third tab beside Cover page (all clients) and General information.

1 One list, not one per client

A row is written once and shared by every client. That is the whole point: “Care label” is a different layout for each client, so a per-client list would have to be re-done for every customer we take on and would never be finished.

The rows are the shared targets. This screen decides what a row is called and what it says — and, at the bottom of each row, which Monday trim values land on it (section 3).

1The buyer writes a trims list on Monday, in their own words.
2Each of those words is matched onto a packaging row — from this screen, row by row, or from Settings ▸ Trims, value by value. One mapping, two views of it.
3This screen decides the wording that row prints — its name, its note, and its two status wordings.
4The cover page prints the order’s list, one line per row, with a status beside each.
The same mapping, from the other end

Settings ▸ Trims (guide 2) asks: here is a Monday word — which rows does it mean? It is the queue, worst-first, and it is where you work through vocabulary nobody has mapped yet. This screen asks the other question: here is a line the cover prints — which Monday words land on it?

Neither is a subset of the other, and they are not two mappings. Both read and write the same one, so a change made here shows up there and the other way about.

  2. 2“Packing instruction — no file, so no delivery status”. Tick this for anything physical with nothing to print: polybags, hangers, cartons, hooks.   3. 3“built in” marks a row that ships with the app rather than one somebody added here. Both kinds are edited the same way.
  4. 4The note is a standing fact about the document. It prints in every state — whether the artwork has arrived or not — so put permanent instructions here, never anything time-dependent.

  6. 6Delivered is what it says once the document is confirmed in the supplier’s folder.

An empty box is not a blank line

Leave either status box empty and the row prints the wording shown greyed inside it — the default. Type in the box only when this particular row should say something different. Today those defaults are “Waiting for Customer Information” and “Approved”.

One Save, and nothing is saved until you press it

Everything on this screen — names, ticks, wording, and the Monday values on every row — is held locally until Save rows. The button is greyed while nothing has changed.

The rows and the value mapping are two different stores, written one after the other by that one button. If the second write fails, the first stands and the screen stays unsaved for the part that did not land, rather than pretending both went through.

3 Which Monday values land on this row

At the foot of each row is the list of Monday Trims values that currently print on it, most-used first, with the number of styles carrying each. Remove one with its ×; add one from Add a Monday value…, which offers everything not already here, again most-used first.

The vocabulary offered is the live one — already narrowed to orders the app will actually print, so words that survive only on long-dead orders are not put in front of you. It is read after the page opens, so for a moment the list says Reading the Monday trim values… while the wording boxes above are already usable.

  1. 1“also on Hangtag” beside a value means it lands on another row as well. That is legitimate — a compound entry like “Hanger & Hangtag” is one Monday line naming two things — but it is shown here so that adding a value to this row never looks like moving it here.
  2. 2Removing the last row a value has is a real decision, not an undo. The value stops printing on covers altogether — the same “not packaging” decision Settings ▸ Trims offers. The row says so before you click, and again underneath.
  3. 3A row you have just added cannot be mapped yet. It says Save the row first — a Monday value can only point at a row that exists. Save, and the picker appears.
  4. 4Adding a value here settles it. A value that was following the keyword rules becomes a decision of yours, keeping every row it already named plus this one. Nothing is dropped, and a later rule edit can no longer move it.
If the vocabulary can’t be read

Reading every order’s Trims column is the one part of this screen that can fail on its own. When it does, the pickers stand down and say so rather than showing an empty list that would read as “no values on this row”. The row names and wording still save normally, and Settings ▸ Trims still works.

5 When a change reaches a supplier

Changes apply to newly generated bundles

Editing a row changes what is generated from now on. A cover PDF already sitting in a supplier’s folder keeps the words it was built with until it is rebuilt.

To push a wording change out to bundles that already exist, use the tools on the General information tab next door — Regenerate a style for one order, or Apply to existing bundles for a whole client. Guide 4 covers both.

And right now, none of it prints yet

Everything this screen writes — the buyer’s own trims wording, the standing notes, the two status wordings — reaches a cover page only when Print the Monday Trims list on cover pages is on, under Settings ▸ Cover page. That switch is off in production today, so covers print exactly as they always have: the documents this app produces, and nothing new underneath them.

The switch is all-or-nothing on purpose. An earlier version let the notes through while the list stayed hidden, which would have changed what a supplier reads before anyone had decided it should. So edit and prepare the rows freely — nothing you write here reaches a supplier until somebody turns the switch on and a bundle is generated afterwards.

6 Adding and removing rows

Add a row when the buyer keeps asking for something the list has no line for. A new row changes nothing on its own — nothing resolves to it until a Monday value does. Give it a name, press Save rows, and its value picker appears; then map the wording onto it, from this screen or from Settings ▸ Trims.

Remove doesn’t delete — and no cover changes because of it

Remove retires a row. It stops being offered when anybody maps a new value, and it disappears from this list. What it does not do is break anything already pointing at it: a trim value mapped to a retired row keeps printing that row, under that row’s name, with that row’s note and status wording, until somebody re-maps it deliberately.

That is on purpose. Rows are referred to by an id that outlives their name, so genuinely deleting one would silently re-open every mapping that named it — and a cover would quietly change for orders nobody was looking at.

Retired rows are hidden rather than gone. Show N removed rows at the foot of the list brings them back into view, each marked as removed, with Restore to put it back in circulation.

So the sequence for genuinely retiring a line is: re-map the values that point at it (section 3, or Settings ▸ Trims), then remove the row.

Rule of thumb: the row name is what it is, the note is what is always true about it, and the two status boxes are where it has got to. If you find yourself wanting to write “still waiting” in the note, that belongs in the Not yet delivered box instead.
