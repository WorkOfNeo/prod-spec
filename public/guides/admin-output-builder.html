Output Builder — designing a print layout

The Output Builder is where you draw a reusable print template — a care label, price sticker, carton marking, hang-tag — position text and graphics on a true-size page, and wire in the variables that fill it per style. This guide walks every control on the screen: what it means and how to use it.

Admins only · open it at Output builder ▸ click a layout (or + New). The ? beside Save / Open PDF opens this guide in a side panel while you work.

0 How a layout becomes a printed document

A layout on its own prints nothing. It becomes a real output only after you Publish it and add it to a style's Prod Spec. Keep this five-step path in mind — most of the builder's settings make sense once you see where the output ends up.

1Design the layout here — page size, blocks, variables — with a real test style in the live preview.
2Publish it. Publishing validates every variable and turns the Draft into a versioned, usable output layout:<id>.
3Add it to a Prod Spec (Prod specs ▸ open a spec ▸ add output). Only then is it attached to styles.
4Generation renders a PDF per style (and per size/EAN, if you set it to repeat), filling the variables from that style's data.
5Review — each PDF is approved or rejected, then sent to the supplier from the style page.
Once published, edits go live on save

A Published layout is used by every spec that references it. Your next autosave changes what those specs generate from then on — there's no separate re-publish step for edits. Draft layouts are private until you publish.

2 Test data — preview with a real style

Pick a customer and business area; the builder finds real styles for that pair and previews your layout against one. This only drives the preview — it has no effect on what the output generates in production.

  2. 2Search — jump to a specific style number or PO instead of cycling.
  3. 3◀ Style ▶ — step through the matches, ranked fullest first (the styles that fill the most of your variables come first, so you preview against complete data).

Your test style now stays put

Editing the layout re-ranks the fullest-first list in the background, but the style you're previewing stays selected — the preview no longer jumps back to the first style each time. Changing customer, business area or the search is what re-picks a style.

  2. 2Margins — an inset from the paper edge that the whole grid (and every block) sits inside. 🔗 linked drives all four sides from one value; click it to switch to per side (Top / Right / Bottom / Left). Type decimals with a comma or dot.

Print guides — sewing lines, folding lines & the centre hole

Below the grid, add non-printing reference rules: a sewing line a fixed distance from the top or bottom edge (the seam allowance), and a folding line down or across the centre. They appear on the canvas and in the true render to help you place content, matching how the label is sewn or folded.

Centre hole — the punched hang hole on a tag. Tick it, then set the diameter in mm and how far the hole sits from the top or bottom edge. It's always centred across the page, and the distance is measured to the hole's centre — the panel spells out how much clear stock that leaves (Ø 5 mm at 8 mm from the top = 5,5 mm of stock above it). It draws as a dashed circle on the canvas and in the render, so you can keep text and barcodes clear of what the punch removes; nothing is knocked out of the design.

5 The block inspector — styling a block

With a block selected, the right rail shows everything about it: where it sits, how the text is styled, and — at the bottom — its content. All of it autosaves.

Layout controls

  • Column / Row / Width / Height — the block's cell position and span. Type exact numbers when dragging isn't precise enough. The ≈ mm readout shows its real printed size.
  • Align (left / center / right) and Vertical (top / middle / bottom) — where the text sits inside the block.
  • Font size in pt. Barcodes and wash symbols scale with the font size — bump the pt to enlarge a barcode.
  • Bold and Line height (1.2–1.8).

Box & fit controls

  • Border — width (0.2–2 mm), colour, and inner padding (linked or per side). A framed field.
  • Invert — text on a solid block. Black box / white text by default; pick any background and text colour with the swatch or by typing a hex value (#1a4d2e), and reset puts either one back to the default.
  • Fit width — force the text onto one line and auto-scale it to fill the block's width.
  • Shrink to fit cell — reduce the text until it fits its box, so it never overflows onto neighbours.
The content box — one line per printed row

Each line in the content box is one printed row. Type {{ to open variable autocomplete; wrap a selection in **bold** or _italic_ (the B / I buttons do this) to style part of a line. Literal text prints as-is; variables resolve at generation. What you type is exactly what the preview and the PDF render.

6 Variables — the heart of a layout

Variables (also called tokens) are {{placeholders}} that fill from the style's data at generation. The Variables palette on the right lists them by group; click a chip to insert it at your cursor. Tick Show values to resolve every chip against the current test style so you can see real data.

Size runs that carry two forms — cm and age

Kids' size columns are often filled with both forms in one label: 86-92 cm / 1½-2 år, 98-104 cm / 3-4 år, …. Which one a label prints is per output — the palette offers three chips for the Coop size range:

  • {{sizeRangeCoop}} — the label as the buyer wrote it: 86-92 cm / 1½-2 år - 98-104 cm / 3-4 år
  • {{sizeRangeCoop:numeric}} — the measurement only: 86-92 cm - 98-104 cm
  • {{sizeRangeCoop:year}} — the age only: 1½-2 år - 3-4 år

The split is by the age unit (år, mdr, years, months…), never by the slash on its own — so a size that is slash-written, like 86/92, is never cut in half. A run with no age half prints as authored for every chip, so a form is safe to set on a layout whose styles don't all carry both. Sizes that end up printing the same text (two ages sharing one measurement) collapse to one entry, and the current size is still enlarged.

Graphics — rendered as images, scaled by the block's font size.

Barcodes {{barcode:cartonEan}} carton EAN as Code 128; {{barcode:cartonEan13}} the same carton number as a true EAN-13; {{barcode:ean13}} the first size's product EAN-13. Add a bar height in mm: {{barcode:ean13:8}} (2–40 mm).
Wash symbols{{washSymbols}} the style's care icons as a row. Optional mm gap between icons: {{washSymbols:0}} (0 = flush).
Logos{{logo:contrast}} / {{logo:contrastAddress}} the built-in Contrast marks; {{logo:custom}} this layout's own uploaded logo (see §7).
Certificate marks{{cert:oekotex}} {{cert:fsc}} — self-gating: a mark prints only on styles whose Certificates field declares it. No {{if}} wrapper needed. Artwork comes from Settings → Certificates (a placeholder shows until the licensed mark is uploaded).
🔀 Logic — {{if …}}{{else}}{{endif}}
Conditional text, one condition per line, no nesting. The condition field must be a text variable.
  • == / != compare the whole value, case-insensitively:
    {{if deliveryTerm == FOB}}…{{else}}…{{endif}}
  • includes / !includes test a comma-separated list:
    {{if certificates includes FSC}}FSC certified{{endif}}
🧮 Calculated — {{= … }}
Arithmetic over field values, useful on multi-style cartons.
  • + − × ÷ on numeric fields: {{= qtyPerCarton * 2 }}
  • sum / count / min / max(field) across the styles on the carton (base + picked siblings; an empty slot counts as 0): {{= sum(qtyPerCarton) }}
  • round(…, decimals) to tidy the result.
Sibling styles — putting several styles on one carton

When Multiple styles on the box is on (§7), a carton layout can place OTHER styles from the same PO via slot tokens: {{style2}} (the headline number) and its fields {{style2Name}}, {{style2Description}}, {{style2QtyPerCarton}} … up to 8 slots. Pick the slot from the palette's Sibling styles dropdown. Branch the single- vs multi-style look with {{if multipleStyles == true}}…{{else}}…{{endif}} — note ==, not ===.

On the canvas and in the content box, variables are colour-coded: known muted, {{if}}/{{else}} italic, {{= calc}} blue (red if the expression is invalid), and {{unknown}} red — an at-a-glance check before you publish.

The moment your design uses {{logo:custom}}, a Custom logo control appears here: upload an SVG / PNG / JPG (under ~450 KB) for this layout, and set its printed width as a % of its block (height keeps the aspect ratio). It's stored per layout, separate from the autosave.

Edit as JSON

At the bottom of the right rail, Edit JSON directly exposes the whole layout — pages, margins, blocks, repeat / split / file-name settings — as one JSON document. An escape hatch for bulk tweaks and copy-paste between layouts; it's validated before it applies.

9 The Settings & Reviews tabs

⚙️ Settings tab
Generation activity — how many PDFs this output has ever produced (total / approved / pending / rejected), across how many styles, and when it last ran.
Auto-approve outputs — a switch that marks this output's assets approved the moment they generate, skipping the manual review queue. Two guards stay: a print-unsafe document (missing artwork or EAN) still falls back to manual review, and a person still presses “Approve all & publish” on the style to send to the supplier.
Generation rules — which styles this output is made for. With no rule it generates for every style whose Prod Spec declares it. Generate when narrows it to matching styles only — a barcode sticker that exists just for shoes is Generate when · Product group · contains · shoes, and no other style gets it. Don't generate when is the opposite: an exception carved out of the default. Keywords are comma-separated and case-insensitive (“contains” matches substrings, “equals” needs the whole field), a Don't-generate match always wins, and a skipped output shows its reason on the style and review screens instead of looking like missing work. The same editor sits in Document types (next to New layout) when a rule should cover a whole type rather than one output.
🗂️ Reviews tab
The most recent PDFs this output produced, newest first — style, file name (with a placeholder-count flag), status (Pending / Approved / Rejected), when it generated, and a link to Open PDF. The tab shows an amber count when any are awaiting review.
Open a style's review screen from here to actually approve or reject.
In one line: draw blocks on the true-size grid, fill them with {{variables}} from the palette, watch the true-render preview against a real style, set repeat / file-name / carton options, then Publish and add the output to a Prod Spec so it generates.
